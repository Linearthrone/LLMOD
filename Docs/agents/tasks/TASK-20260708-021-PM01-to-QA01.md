# Task · Runtime regression — computer_use tool invocation (control ON)

## Problem description

DEV-017 fixed the code/config side (unified Hermes dir, `computer_use` in persona setup,
`AllowComputerControl` toggle, tool-guide gating). OPS-020 applied it on the live box and returned
**READY** (97 tools / 7 servers / 0 MCP failures, gateway on new Release build).

The original blocker (`ISSUE-20260708-002`) was behavioral: **`mcp_computer_use_computer` registers
but the model does not reliably invoke it** on a natural screenshot request. This ticket proves
(or fails) that end-to-end with `AllowComputerControl` ON.

## Preconditions (OPS-020 left the box in this state)

- `HouseVictoria.App.exe` (Release) may already be running as sole `:8642` owner (PID from OPS
  report ~107324 / gateway python ~68012). If not running, start the Release build — do **not** also
  start the `Hermes_Gateway` scheduled task (dual-owner footgun).
- Default model: `qwen3-coder:480b-cloud` (coder-biased; may reach for terminal first — note which
  tool it picks).
- Authoritative Hermes dir: `%LOCALAPPDATA%\hermes`.

## Steps (capture real output for each)

### A) Toggle & persistence

1. Open Settings → Instrument Stack drawer. Confirm **"Let Victoria control my screen"**
   (`AllowComputerControl`) checkbox exists near the share-screen toggle.
2. Turn **AllowComputerControl ON**. Optionally turn **Share screen with Victoria ON** as well
   (tests the combined path DEV-017 documented).
3. Restart the app. Confirm the checkbox state **persists** (round-trips via `user-settings.json`).

### B) Behavioral tool-invocation test (core acceptance)

4. Tail or snapshot `Media\hermes-gateway.log` (or `%LOCALAPPDATA%\hermes\logs\agent.log`) with a
   timestamp marker **before** sending the message.
5. As the **primary persona** (Hermes path, `PrimaryLLM=hermes`), send a benign natural-language
   request, e.g.:
   > "Take a screenshot of my desktop and tell me the active window title."
   Do **not** name the tool explicitly in the message (no "use mcp_computer_use_computer").
6. After the reply completes, inspect the gateway log for evidence of a **`computer_use` /
   `mcp_computer_use_computer`** tool call (tool invocation line, action=snapshot or similar).

### C) Negative control (optional but recommended)

7. Turn **AllowComputerControl OFF** (share may stay ON). Send the same screenshot request again.
   Confirm the log does **not** show a `computer_use` invocation (and/or the reply declines or
   asks for an upload — consistent with the forbid guidance).

## Acceptance criteria (state Pass/Fail for each)

| # | Criterion | Pass |
|---|---|---|
| 1 | `AllowComputerControl` toggle visible in UI | Checkbox present in Instrument Stack drawer |
| 2 | Toggle persists across app restart | ON state survives restart |
