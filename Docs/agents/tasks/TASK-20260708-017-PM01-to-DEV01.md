## Background

Computer-use (mouse/keyboard/screen automation) is **not** implemented in the C# app or the Python
MCP server. It is delegated to external **Hermes Agent** (`:8642`) + the **`computer-use-mcp`** npm
server Hermes spawns via `npx`. Investigation found several code-level reasons the capability is
fragile or silently unavailable. This ticket fixes the **code/config-authoring** side. A parallel
OPS ticket (`TASK-20260708-018`) validates the live runtime on this machine.

Do **not** implement native WPF desktop automation — keep Hermes as the control plane.

## Problems & root causes (precise)

1. **Hermes config/env path is split**, so MCP registration and `.env` keys can land where the
   gateway won't read them:
   - `Tools/setup-hermes-integration.ps1` resolves config via `hermes config path` → typically
     `%LOCALAPPDATA%\hermes\config.yaml`.
   - `Tools/setup-persona-mcp.ps1:12` hardcodes `%USERPROFILE%\.hermes\config.yaml`.
   - `HouseVictoria.Services/Hermes/HermesGatewayService.cs:92` loads `.env` only from
     `%USERPROFILE%\.hermes\.env`.
2. **`computer_use` is not surfaced to the model.** `HouseVictoriaToolCatalog.BuildHermesToolGuide`
   (`HouseVictoria.Services/Persona/HouseVictoriaToolCatalog.cs:29-54`) lists only MT4 + file tools;
   nothing tells the persona that desktop control / terminal / browser exist.
3. **"Share screen" blanket-forbids control.** When `ShareScreenWithAI` is on,
   `HermesAIService.cs:242-268` attaches a screenshot **and** injects "do NOT call the computer_use
   tool". There is no way to both share the screen *and* let Victoria act on it. The only flag today
   is `ShareScreenWithAI` (`IAgentDesktopMonitorService.cs:23`); there is no "allow control" concept.
4. **Persona setup script doesn't register `computer_use`.** `setup-persona-mcp.ps1` wires the
   `house_victoria` stdio MCP only; only `setup-hermes-integration.ps1:184-190,305-309` adds
   `computer_use` (and only when `-SkipComputerUse` is not passed).

## Solution (scope)

1. **Unify Hermes dir resolution** into one shared helper used everywhere:
   - Add a single resolver (prefer `hermes config path`, else `%LOCALAPPDATA%\hermes`, else
     `%USERPROFILE%\.hermes`) and use it in `HermesGatewayService.cs` (config + `.env`) and in
     `setup-persona-mcp.ps1`. Both scripts and the gateway must agree on the same directory.
   - `.env` load in `HermesGatewayService.cs:92` must use the resolved dir, not a hardcoded
     `%USERPROFILE%\.hermes`.
2. **Register `computer_use` in persona setup too** (`setup-persona-mcp.ps1`), or have it call the
   shared MCP-block writer, so a persona-only setup run does not drop desktop control. Respect an
   opt-out switch consistent with `-SkipComputerUse`.
3. **Split "passive share" vs "allow control":**
   - Add `AllowComputerControl` (bool) to `IAgentDesktopMonitorService` + implementation +
     `AgentDesktopDrawerViewModel` + a checkbox in `InstrumentStackDrawer.xaml` near the existing
     "Share my screen with Victoria" toggle.
   - In `HermesAIService.BuildUserContent` (`:240-269`): only inject the "do NOT call computer_use"
     guidance when `AllowComputerControl == false`. When control is allowed, attach the screenshot
     (if sharing) **without** forbidding the tool, and add a short line telling the model it MAY use
     `computer_use` to act.
   - Default `AllowComputerControl = false` (safety); persist via AppConfig like other settings.
4. **Add a computer-use section to the Hermes tool guide** (`BuildHermesToolGuide`) that briefly
   documents `computer_use` (screenshot/click/type/scroll), terminal, and browser — gated so it only
   appears when control is enabled, to avoid nudging the model to grab the desktop unprompted.

## Do not touch

- Ollama/LM Studio direct-chat routing behavior (companions stay tool-less by design).
- The actual `computer-use-mcp` npm package (external).
- Business/persona prompt content beyond the tool-guide additions above.

## Acceptance criteria

- One shared Hermes-dir resolver; `HermesGatewayService` and both setup scripts use it (show the
  resolved path in logs).
- Running `setup-persona-mcp.ps1` on a clean config yields a `config.yaml` containing **both**
  `house_victoria` and `computer_use` MCP blocks (unless opt-out passed).
- New `AllowComputerControl` toggle exists in Settings UI and persists across restart.
- With **share ON + control OFF**: message still contains the "do NOT call computer_use" guidance.
- With **control ON**: guidance is absent and the tool guide includes the computer-use section.
- App builds clean (`dotnet build`), no new warnings in changed files.
