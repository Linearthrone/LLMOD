# Task · Wire computer-use tool guide into Hermes desktop/remote path

## Problem description

QA-021 **FAIL** (report: `Docs/agents/reports/TASK-20260708-021-QA01-to-PM01.md`).

DEV-017 + OPS-020 plumbing works: `AllowComputerControl` persists, inline guidance injects on
control ON (`[You MAY use the computer_use tool…]`), and `mcp_computer_use_computer` registers
(97 tools / 7 servers). But on a **natural** screenshot request via the remote companion path,
`qwen3-coder:480b-cloud` invoked **`browser_vision`** instead of **`mcp_computer_use_computer`**.
`browser_vision` failed (model lacks vision), and the reply **hallucinated** a window title.

Negative control (control OFF) correctly suppressed all tool calls — suppression works; selection
does not.

## Root cause (precise)

1. **Tool guide gap on the Hermes path QA actually tested.** DEV-017 added the computer-use section
   to `HouseVictoriaToolCatalog.BuildHermesToolGuide(…, includeComputerUse)` but wired it only in
   `SMSMMSCommunicationService.cs:693`. The remote companion and main desktop chat go through
   `HermesAIService` → `BuildUserContent` (`HermesAIService.cs:243-295`), which injects only a
   short inline suffix — **not** the full tool guide that names `computer_use (action=screenshot)`
   and says "take a screenshot first."
2. **Model picks the wrong vision tool.** With ~97 tools and no explicit desktop-screenshot routing,
   `qwen3-coder` prefers Hermes's built-in `browser_vision` for "screenshot" wording.
3. **Secondary:** long conversation history (`history=24`) may bias replies; not the primary fix here.

## Solution (scope)

1. **Inject `BuildHermesToolGuide` on the Hermes path when control is ON.**
   - In `HermesAIService` (or a shared helper it calls), when `_desktopMonitor.AllowComputerControl
     == true`, prepend or append the tool guide from
     `HouseVictoriaToolCatalog.BuildHermesToolGuide(generatedFilesPath, includeComputerUse: true)`
     to the message the gateway sees — same catalog SMS already uses.
   - Gate it the same way: only when control is enabled (do not advertise desktop control when OFF).
   - Apply to both plain-text and multimodal (`BuildUserContent`) paths so remote companion and
     desktop chat behave consistently.
2. **Steer desktop-screenshot requests away from `browser_vision`.**
   - When control is ON and the user message is desktop-screenshot shaped (e.g. mentions
     "screenshot", "desktop", "active window", "my screen"), add explicit guidance in the injected
     block: **use `computer_use` with `action=screenshot`, NOT `browser_vision` or terminal**, for
     seeing the local desktop.
   - Keep the change minimal — guidance text or tool-guide table row, not a new routing engine.
3. **Do not change** Ollama/LM Studio direct-chat routing, the `computer-use-mcp` npm package, or
   business persona prompt content beyond tool-guide / steering additions.
