## Root-cause analysis (QA)

1. **Wrong tool selection:** With control ON, `qwen3-coder:480b-cloud` prefers Hermes's
   **`browser_vision`** over **`mcp_computer_use_computer`** for "screenshot" wording — same class of
   failure as pre-DEV-017 (coder/browser bias), despite injected allow-control guidance.
2. **No full tool guide on desktop/remote Hermes path:** DEV-017 report notes
   `BuildHermesToolGuide` (computer-use section) is wired on SMS path only; remote companion uses
   `HermesAIService` + short inline guidance, not the full catalog.
3. **Vision model mismatch:** `browser_vision` uses `qwen3-coder:480b-cloud` for vision analysis,
   which rejects image input → tool error → model free-text hallucination.
4. **Conversation history contamination:** `history=24` on both runs; identical "Maestro" reply
   with or without tools suggests strong prior-turn bias. Recommend QA re-test with a fresh contact
   or cleared history.

## Recommendations

1. **DEV follow-up:** Wire `BuildHermesToolGuide(includeComputerUse: true)` into `HermesAIService`
   (desktop + remote paths), not only SMS.
2. **Model/tool routing:** Consider a vision-capable model for auxiliary vision, or block
   `browser_vision` when the request is desktop-screenshot shaped and control is ON (steer to
   `computer_use`).
3. **Re-test:** Fresh conversation (no 24-turn history) + control ON; optionally try
   `gpt-oss:120b-cloud` or another model PM selects for agentic tool-calling.
4. **PM:** Do **not** close `ISSUE-20260708-002` on this result.
