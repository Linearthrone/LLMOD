## Root cause of "Victoria can't use computer-use"

Two real problems, both above the plumbing:

### A) MCP load was racing/failing (FIXED)
The gateway intermittently logged `MCP: registered 0 tool(s) from 0 server(s) (13 failed)` —
~16 cloud MCP servers (alpaca, gmail, github, google-*, sentry, tradingview, elevenlabs, …)
fail to connect via npx/uvx/docker and starve the ones we actually need, so `computer_use`
sometimes never registered. Healthy starts logged `108 tools from 10 servers`.

**Fix applied:** disabled the 16 broken/unused MCP servers in
`%LOCALAPPDATA%\hermes\config.yaml` (backup: `config.yaml.bak-20260708-pm01`). Now every start
is deterministic: `MCP: registered 97 tool(s) from 7 server(s)` with **zero failures**.
Kept enabled: `house_victoria, house_victoria_data, computer_use, filesystem, fetch, git, memory`.

### B) The model does not reliably INVOKE computer_use (OPEN — needs decision + DEV)
Even with `mcp_computer_use_computer` registered, a plain request ("take a screenshot and tell
me what's on screen") is **not** reliably turned into a tool call:
- `gemma4:31b-cloud` — declined (once early it returned a vague "1920x1080 / black rectangle",
  likely a partial/hallucinated call).
- `qwen3-coder:480b-cloud` — called a tool, but chose the **terminal** (coder bias) and tried a
  PowerShell screenshot, then gave up on a syntax error.
- `gpt-oss:120b-cloud` — declined, asked the user to upload an image.

Contributing factors: (1) the tool is exposed as `mcp_computer_use_computer` with an `action`
enum — the name does not signal "screenshot the desktop"; (2) Victoria's Hermes tool guide does
not mention computer-use at all, so the persona is never told the capability exists; (3) a large
(~31k-token) system prompt with ~97 tools makes selection harder for weaker models.

This is exactly what DEV `TASK-20260708-017` should address (surface computer_use in
`HouseVictoriaToolCatalog.BuildHermesToolGuide` + control-mode guidance).
